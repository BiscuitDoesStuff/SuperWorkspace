## Task B: harden git rules (approved)

**Problem.** Shell rules match a command prefix, under top-level `allow *`. These forms bypass every git deny and ask rule:
- `git -C <dir> push`, `git -c k=v reset --hard`, `git --no-pager push`;
- `bash -c 'git push'`, `pwsh -c '...'`;
- rtk's own runners: `rtk proxy|run|err|summary git push`, which rtk passes through unchanged.

**Where the rules live.** The git and `gh` rules (deny: push, clean, reset --hard, stash, `gh`; ask: commit) are generated by the kit source `lib/Sw.Project.psm1`, together with `Add-SwRtkTwins`, and appear in `opencode.jsonc` and the agent frontmatter under `.opencode/agents/`. The static matrix cases are at `lib/Sw.Project.psm1:469` (`Expect ... deny`).

**Plan.**
1. Design the patterns in the Leader session. Candidates:
   - deny the rtk runner forms (`rtk proxy *`, `rtk run *`, `rtk err *`, `rtk summary *`) or set them to ask;
   - add global-flag forms (`git -C * push*`, `git -c * push*`, `git --* push*`, and the same for reset, clean and stash);
   - consider `ask` for `bash -c *`, `sh -c *` and `pwsh*-c *`.
   Check false positives against the allowlisted read commands, `git status && ...` compounds, and rtk twins. Note: OpenCode V2 globbing and last-match semantics apply.
2. Implement with `project-developer`: kit source first, regenerate with `sw update`, no hand edits to generated files. Add `Expect` deny or ask cases for each bypass form, plus allow cases for normal reads.
3. Validate:
   - `pwsh -NoProfile -File .sw/sw.ps1 validate -CheckLinks`;
   - `pwsh -NoProfile -File sw.ps1 update . -WhatIf` shows no drift;
   - `git diff --check`.
   Optional: a scratch runtime check, 1 run per bypass form with a free Zen model, only with the owner's go-ahead.
4. Record and close: `CHANGELOG.md`, the S4 note in the outline, the state Startup, and a closure event. The limit stays documented: denies stop calls, not effects.
