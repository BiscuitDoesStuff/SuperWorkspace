## Design adjustments during implementation

- `*rtk run *git*` instead of `rtk run *git*`. `Expect` also tests the `rtk `-prefixed value.
- `pwsh|powershell *git*` instead of `*-c*git*`, and explicit case variants for the encoded flags. CI (`sw-validate.yml`) runs on ubuntu, where matching is case-sensitive, so `-Command` would not match `-c`. The developer re-ran the wrapper and allow values under case-sensitive matching: 0 mismatches.
- No literal-newline rule. The frontmatter parser rejects backslash escapes.

## Known false positives and remaining gaps

**False positives:**
- A command whose text contains ` git <verb> ` is denied, for example a commit message mentioning git push.
- `git -C . log --grep push` is denied.
- Any `pwsh` call that mentions git, including in a path, asks.
- `project-review` cannot pipe or redirect, and `git log --format='%h <%an>'` is denied.

**Not caught:**
- a wrapper behind a compound (`x && bash -c 'git push'`);
- `$(git push)` and backtick forms in writer roles;
- a newline-separated second command in writer roles;
- scripts written with `write` and then run.

The documented limit stands: a shell rule stops the call, not the effect.

**Unknown:** whether OpenCode 2.0.20 splits compound commands before matching. If it does, the compound rules are redundant but harmless.
